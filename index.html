Can an agent actually build on these apps?

A comparative assessment of 100 applications across 10 categories, focused on the practical gap between “an API exists” and “an agent can reliably use it”.

Headline finding: API availability alone does not make an app agent-ready. The real constraints are credential eligibility, permission scope, commercial gates, MCP tool coverage and safe write access.

Findings at a glance

1 · API ≠ buildability

A documented REST or GraphQL API is only the starting point. A real integration also needs usable credentials, permissions, quotas, pagination/webhooks and the right read/write operations.

2 · MCP ≠ full product access

An MCP server may expose only selected workflows, may be beta or read-only, or may require a paid tier, OAuth setup or admin approval. Tool coverage must be inspected, not assumed.

3 · Access gates shape effort

OAuth and user-delegated access suit multi-tenant apps; personal tokens can simplify prototypes. Partner review, enterprise plans, API credits and production approval can still block a build.

What the dataset captures

For each application: one-line purpose, authentication, self-serve vs gated credential setup, API type and breadth, MCP/agent tooling, buildability verdict, primary blocker and source links.

Decision rule: classify as buildable only when the access path and required operations are plausible; call out gating and unknowns rather than treating them as failures.

What the agent does — and where the human stays in the loop

Catalogue

Reads the 100-app, 10-category CSV inventory and keeps the target research fields consistent.

Discover

Creates a Composio session, searches for the Keenable web-search tool through MCP and discovers the tool schema.

Research

Executes targeted app queries and stores up to five search results per app as evidence leads.

Review

Audits URLs, prioritises first-party docs and writes evidence/status fields. Human review validates page claims and final buildability.

Automation proof

Demonstrated successfully

Composio MCP initialized; COMPOSIO_SEARCH_TOOLS discovered KEENABLE_SEARCH_WEB_PUBLIC; COMPOSIO_MULTI_EXECUTE_TOOL successfully ran a Salesforce official-docs search and returned five results. The separate research run saved 500 result records for 100 apps with zero recorded search failures.

This proves the research/search workflow, not live API integrations with all 100 vendors.

Human checkpoints / misses

  • Search results are leads, not verified facts; source relevance and authority need review.
  • Page access can fail or content may not establish every field.
  • Exact scopes, plan eligibility, API limits, tool inventory and write permissions need human inspection.
  • Fanbasis and Sherlock remain source gaps in this snapshot.
